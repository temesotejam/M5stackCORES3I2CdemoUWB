# Type2DK PIO12・PIO13のI2C調査（2026-09-16）

## 判定と、試験版の誤り

QN9090のPIO12・PIO13にはハードウェアI2C1のSCL・SDAが割り当てられ、スレーブに使用できる。400 kHzはFast-modeの対応範囲。Type2DKモジュールにも両信号が出ている。

ただし、**本リポジトリのv1〜v3はピン機能番号をFUNC4と誤って指定していた。FUNC4はPWMであり、I2C1はFUNC5。v4で修正した。** チップが対応することと、配布したプログラムが正しく設定されていたことは別だった。

## 一次資料による照合

| 確認内容 | 資料・場所 | 結果 |
|---|---|---|
| I2C1のピンとmaster/slave対応 | [NXP QN9090(T)/QN9030(T)データシート Rev.1.2](https://www.nxp.jp/docs/en/nxp/data-sheets/QN9090%28T%29QN9030%28T%29.pdf)、p.16、Table 5 | PIO12=I2C1_SCL、PIO13=I2C1_SDA |
| 正確な機能番号 | [NXP JN-AN-1252 Rev.1V2](https://www.nxp.com/docs/en/application-note/JN-AN-1252.pdf)、p.2、3.1の表 | 下表のFUNC2/4/5 |
| モジュール内の接続 | [村田Type2DK公開データシート（Mouser配布）](https://www.mouser.com/pdfDocs/SP-ZZ2DK-forWEB.pdf)、冊子p.10 / PDF p.11 | モジュール端子54・55からQN9090 PIO12・13へ接続 |
| 速度 | NXPデータシートp.37、8.13、およびp.66、Table 39 | Standard-mode 100 kHz、Fast-mode 400 kHz。1 MHz以上の対応は特定I2C端子に限定 |
| 既知の制限 | [NXP QN9090 Errata Rev.3.0](https://www.nxp.com/docs/en/errata/QN9090_ERRATA.pdf) | 掲載されている4項目に、PIO12/13のI2C1利用を禁止する記載はない。未掲載不具合の不存在を保証するものではない |

| QN9090信号 | FUNC2 | FUNC4（旧版の誤設定） | FUNC5（正しい設定） | Type2DKモジュール端子 |
|---|---|---|---|---|
| PIO12 | SWCLK | PWM0 | I2C1_SCL | 54 |
| PIO13 | SWDIO | PWM2 | I2C1_SDA | 55 |

表はPDFを描画して列位置も確認した。データシートの「機能の説明一覧」は未使用機能を省略しており、その列挙順を機能番号として数えてはいけない。

54・55はモジュールの端子番号。ユーザーのEVKはRev.4.1であり、この調査では同リビジョンのコネクタ穴番号や直列部品までは確認できていない。SR040側のSR_SWDCLK/SR_SWDIO（モジュール端子3・2）とは別信号である。

## 必要なファームウェア設定

v4では次の設定を使用する。信号線へ出力されるSCLの周波数はCoreS3（マスター）が決める。

| 設定 | v4 |
|---|---|
| PIO12/13のピン機能 | IOCON FUNC=5、デジタル有効、内部抵抗なし、疑似オープンドレイン有効 |
| IOCON設定値 | 両方とも0x00000595 |
| 周辺回路選択 | FLEXCOMM3をI2Cとして選択、I2C1をスレーブ有効化 |
| アドレス | 7ビット0x42、SLVADR0=0x84 |
| 機能クロック | FRO32M由来の32 MHz |
| CLKDIV | 8。スレーブのデータ設定時間を確保する値で、SCLを32 MHz/9で駆動する意味ではない |
| 応答 | アドレス・送信要求・選択解除の割り込みを処理 |
| 省電力 | このI2C単体試験では使用しない |

ユーザー提供SDKの `fsl_i2c.c` の `I2C_SlaveDivVal` / `I2C_SlaveInit` と照合した。32 MHz・Standard-modeではCLKDIV=8になり、SDKのコメントも速度未確定時は長い設定時間のStandard-mode設定を使うとしている。従ってCLKDIV=8自体は「400 kHzに対応しない」という意味ではない。ハードウェアは必要に応じてクロックストレッチする。

SWDとI2Cは同じ2ピンの機能選択なので、I2Cに切り替えた状態で同じピンをSWDとして同時使用できない。既存SWDプローブは外す。USB書き込み・ログに使うPIO8/PIO9のUART経路は別である。

## 電気的条件と400 kHzの確認

PIO12/13は通常I/OセルによるI2Cで、PIO10/11の専用I2Cセルとは区別する。1 MHzや3.4 MHzの対応をそのままPIO12/13へ適用しない。

3.3 VのI/O電源で使う場合は、SDA・SCLをそれぞれ3.3 Vへ外付けプルアップし、GNDを共通にする。PORT Aの赤5 Vへはプルアップしない。短い配線では各2.2 kΩを試験開始値にできるが、最終値は電源・並列抵抗・バス容量と波形で確認する。NXP Table 17にはPIO12/13を含むLS端子の2 mA負荷条件がある。3.3 V/2.2 kΩは最大約1.5 mA（他の抵抗が並列にない場合）。

SDK・レジスタ・ビルドの確認だけで、400 kHzの波形、割り込み応答、UWB/BLEとの同時運用を検証したことにはならない。今回のv4はUWB/BLEを動かさない単体試験。後でUWBと統合する際は省電力も見直す。NXP Table 8（p.30）はI2C1のPower-downからの直接wake-upを対応ありとはしていない。

## 現在のログについて

ユーザーのCoreS3ログは100 kHz、受信成功0回、未通信時にもidle=0/0。2DK USBログは無出力との報告。旧版でPWMを選んでいたことは確定したソフトウェア不具合であり、I2Cが端子へ出ない原因になる。ただし両線Lowの物理原因やUSB無出力の原因を、この誤設定だけで確定することはできない。

旧版のready=1は、誤った設定値を書いて同じ値を読み戻した場合にも成立するため、機能番号の誤りを検出できなかった。v4には実際のピン設定ヘルパーを公式表のFUNC5と照合するホスト回帰テストを追加した。FUNC4へ戻した場合にテストが失敗することも確認する。

## v4で確認する順番

1. 機器間の配線を外し、2DK単体へv4を書き込んでFlash照合を確認。
2. 2DK USBを115200 bps / 8N1 / フロー制御なしで開き、STATE,v=4を確認。
3. REGのpio12/13が0x00000595であることを確認。
4. 電源を切ってSDA/SCL/GNDとプルアップを接続し、100 kHzのPROBE/READを試す。
5. 100 kHzで応答を得てから400 kHzを試す。

**実機での起動・通信成功はまだ未確認。v4は判明した設定ミスを修正した版である。**
