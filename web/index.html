ファームウェアを確認しています…

CoreS3の現在のアプリを書き換えます。「Erase device」を選ぶと保存データも消去されます。接続できない場合はRESETを約3秒長押しし、緑のLED点灯後に離してから再接続してください。

書き込み後に画面が出ない場合は、RESETを短く押してください。

02 / 3本を接続する

双方を個別にUSB給電。PIO12・PIO13の外付けプルアップは基板回路図にありません。SDA・SCLは電圧を確認した2DKのMCU I/O電源（TP18）へ、それぞれ2.2 kΩでプルアップする構成から試します。既存抵抗・バス容量・波形を確認し、SWD書き込み器は外してください。

Rev.4.1回路図でTP8のピン番号を照合済み。TP14はSR040用です。実物の1番表示を確認してください。USB電源経路にはダイオードがあり、MCU電圧は3.3 V固定ではありません。TP18（MCU電源）とTP15（GND）の電圧を先に確認します。COMポートが見えてもMCU給電の証明にはなりません。

2DK側のUSBログも確認する

2DK診断版 v4は、PIO12・PIO13をFUNC5（I²C1）へ修正しています。旧v1〜v3はFUNC4（PWM）を選んでいたため、v4に更新してください。既存USBから起動・I²C設定・アクセス回数を出力します。まず機器間の配線を外し、2DK単体のUSBログを確認してください。CoreS3 1.1.0の再書き込みは不要です。実機での解消は未確認です。CoreS3の書き込みボタンでは2DKを書き込めません。

2DK診断版BINをダウンロード

DK6Programmerで書き込み・照合後、2DKのCOMをTera Termなどで 115200 bps / 8N1 / フロー制御なし で開きます。旧測距版の3000000 bpsとは異なります。

.\DK6Programmer.exe -V 0 -P 1000000 -s COM22 -Y -v -p .\2dk_i2c_diag_v4.bin

COM22は例です。書き込み時はシリアルモニターを閉じます。STATE,v=4,beat=... が定期的に出ればアプリが動作しています。PROBEでwrite_addr、READでread_addr・tx_bytesが増えるか確認します。REGのpio12・pio13は0x00000595が期待値です。ready=1は設定の読み戻し一致を示し、通信成功の証明ではありません。

2DK診断版の手順とログ説明 / PIO12・PIO13の調査根拠

03 / 100 kHz → 400 kHzを試す

  1. 2DKに上記の診断版v4 を書き込んで起動します。このページで書けるのはCoreS3だけです。
  2. CoreS3は起動約5秒後から100 kHzで受信します。OKが増え、IO / BAD / GAPが0なら正常な応答です。
  3. 画面の400 kHzを押し、同様に確認します。読み取り頻度は最大約50回/秒で、I2Cクロックとは別です。
  4. AUTOで各速度500回ずつ試験します。約20秒後、両方が成功するとAUTO PASSになります。2DK起動完了後に開始してください。

PROBE：0x42のACK確認（USBログ出力） / PAUSE・RUN：停止・再開 / CLEAR：集計リセット

この試験は固定パターン・連番・XORの受信確認です。距離を測るファームウェアではありません。AUTO PASSは今回の配線・条件でのソフトウェア試験結果であり、400 kHzの波形や立ち上がり時間はオシロスコープ等で別途確認してください。

診断版 v1.1.0

外部I²CをEspressif標準ドライバで動作させ、NO_ACK（0x42からACKなし）、TIMEOUT、BAD_FRAMEを分けて表示します。内部タッチ用I²Cとは別のコントローラを使用します。

起動5秒後に0x42を自動PROBEし、USBへ毎秒 DIAG を出します。書き込み後10秒ほど待ち、PROBEとDIAGの行を確認してください。USBで p を送っても再PROBEできます。

before / after / idle はSDA/SCLのデジタル値（1=High、0=Low）。read=WAITのbefore/afterは初期値なので、未通信時はidleを見てください。1/1でも外付け抵抗や配線の正しさは証明できません。0が続けば、その線がLowに保持されている可能性があります。電圧や立ち上がり時間の測定値ではありません。

今回の変更は切り分け用です。2DK側の応答形式は各版で共通です。実機での原因解消を確認した版ではありません。

応答しないとき

IOが増える：2DKのファームウェア、起動待ち、信号名、GND、プルアップを確認。BADが増える：16バイトの形式不一致またはデータ化け。100 kHzのみ成功：配線を短くして、プルアップと波形を確認してください。

USBシリアル115200 bpsでは STAT,clock,attempts,ok,io,bad,gaps,sequence,maxUs を表示します。Web書き込みとシリアルモニターは同時にポートを開けません。
